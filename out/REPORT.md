## 2. 方法

- 合法身份须同时满足：数字对应 `str(int(id)) == token`、在该批该 shard 白名单内、批内每个原始 ID 至多一次；同一 ID 收到相同 rev 而 (deleted, amount) 不同的解释非法。
- 确定整批解释后，每个 ID 跨四批取最高 rev 为胜者；墓碑参与胜出，胜者为墓碑则该实体不计金额与笔数；活的零金额仍计一笔。
- 全部合法联合解释用 0-1 整数规划刻画（SciPy 1.13.1/HiGHS，`mip_rel_gap=0`）。每个金额端点由一个完整整数见证实现，并用“越界 1 分不可行”的二次求解证明最优；每个见证均经 `audit.evaluate` 逐条复核。
- 每行的可行身份集由逐候选可行性求解确定，排除项以 ILP 不可行为证，并与独立的二分匹配方法互核；`examples/tiny.json` 另用纯穷举互核（4 份合法解释，与 CONTRACT 一致）。

## 5. 身份选择如何改变修订胜者（实例）

以行 B/01（B.csv:2，token=314，shard=wide，rev=7，amount=500）在 coast 分区两个端点见证中的归属为例：

- 见证 w20（coast 下界 -370）：该行归属 `00314`（registry 分区 south），00314 的修订胜者为 rev=7、deleted=0、amount=500（胜者行 B/01，B.csv:2）；此时 `0000314`（分区 coast）的胜者为 rev=13、deleted=0、amount=-200（胜者行 D/01，D.csv:2）。
- 见证 w21（coast 上界 1030）：该行归属 `0000314`（registry 分区 coast），0000314 的修订胜者为 rev=7、deleted=0、amount=500（胜者行 B/01，B.csv:2）；此时 `00314`（分区 south）的胜者为 rev=13、deleted=0、amount=-200（胜者行 D/01，D.csv:2）。

同一导出行的两种归属改变了两个实体各自的最高修订胜者，coast 分区金额因此在 -370 与 1030 之间变动；这证明身份不能逐行独立猜测，修订胜者取决于整批联合解释。

## 6. 墓碑与旧修订为何不能先行丢弃

墓碑参与胜出：见证 w1 中实体 `000314`（registry 分区 south）的胜者是行 B/03（B.csv:4，rev=8）的墓碑（deleted=1），它压过了同实体 rev=5、amount=80 的活行 A/05（A.csv:6）。若先行丢弃墓碑，该实体会被按旧活值计入 south 分区，金额与笔数都会被高估；按规则该实体不计金额和笔数。

旧修订不能先行丢弃：B/02（B.csv:3，rev=3，amount=900）、C/02（C.csv:3，rev=4，amount=650）、C/04（C.csv:5，rev=2，amount=50）、D/03（D.csv:4，rev=1，amount=1000）。每个 314 家族实体在 A 批都带有一行 rev=5（A.csv:2..7），因此这些 rev<5 的行在任何合法解释中都不可能是胜者；但它们仍占据批内白名单名额（例如 B/02 的可行身份有 5 个，见第 3 节），先行丢弃会破坏批内唯一性约束并改变其他行的可行身份集，故必须参与核定。
